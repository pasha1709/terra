# terra
Проект о керамических изделиях: посуда, вазы и предметы декора.

## Локальный запуск

Нужен Node.js 18 или новее. Устанавливать зависимости не требуется.

```sh
npm run dev
```

Откройте http://127.0.0.1:5173. Проверка синтаксиса: `npm run check`.

Реализованы шапка, главный экран, категории «Найдите свой предмет», интерьерная секция «Предметы в вашей жизни», коллекция «Олива и мел», блоки «Характер ручной работы», «С заботой о вашей покупке» и «TERRA для бизнеса» по референсам.

## Фотография

Подключено `assets/terra-hero.png` — чистое предметное фото, восстановленное встроенным imagegen из правой части предоставленного макета. Убраны надписи, плашка и карточка; закрытые ими участки дорисованы. Это реконструкция по референсу, поэтому мелкие детали керамики и ветки могут отличаться. Весь макет как изображение не используется: шапка, заголовки, плашка и карточка остаются HTML.

Миниатюра этой же вазы использует кадрирование фото. При наличии отдельного снимка укажите его в `productImage` в `integrations.js`.

Изображения используют `object-fit: cover`. Положение основного фото задаёт `.hero-image` в `styles.css`, положение миниатюры — `connectImage` в `app.js`. При ошибке загрузки остаётся подписанная область вместо сломанного изображения.

### Остальные разделы

Каталога, новинок, поиска, страниц мастерской/доставки и корзины в исходном проекте нет. В `integrations.js` их значения оставлены `null`. Элементы помечены `aria-disabled` и объясняют недоступность при активации мышью или клавиатурой. Фиктивная корзина и счётчик покупок не создаются.

Укажите реальные URL в `catalog`, `newArrivals`, `atelier`, `delivery`, `search`. Кнопки hero и пункты меню используют эти же подключения.

Для настоящей корзины передайте адаптер `cart`:

```js
cart: {
  open() { /* открыть существующую корзину */ },
  async add(productId) { /* добавить товар через API магазина */ },
  getCount() { /* вернуть актуальное количество товаров */ },
  subscribe(callback) { /* вызывать callback(count) при изменениях */ },
}
```

Идентификатор товара в обработчике: `forma-04`. Счётчик обновляется только по состоянию подключённой корзины, после успешного добавления. Ошибки объявляются через `aria-live`.

## «Предметы в вашей жизни»

Локальный адрес секции: http://127.0.0.1:5173/#in-life.

Отдельного товарного блока в текущем проекте нет. Интерьерная секция расположена после категорий; следующая секция — коллекция «Олива и мел». Будущую товарную сетку следует разместить перед `#in-life`. Остальные секции и их стили не изменены.

Три отдельных фото `assets/inspiration/living-room.png`, `kitchen.png`, `bedroom.png` восстановлены встроенным imagegen по соответствующим фотографическим областям пользовательского референса, без текста, плашек и меток. Это реконструкции: отдельные детали могут отличаться от макета. Недостающих файлов изображений нет; оригинальные фото можно подключить вместо реконструкций.

`scenes.js` хранит подписи, alt, описательные названия изображённых предметов, `productId`, координаты меток и `object-position` в процентах исходной фотографии. Для desktop/tablet/mobile заданы отдельные настройки. `scene-geometry.js` пересчитывает координаты с учётом `object-fit: cover`; метки не зажимаются у края поверх других предметов. `ResizeObserver` обновляет положение при изменении размера. Область нажатия — 44 × 44 px, видимый круг — 32 px.

Требуется связать три сцены с реальными товарами: синей скульптурной вазой, селадоновым чайником с бамбуковой ручкой и бордовым витым подсвечником. Сейчас все три `productId` равны `null`: каталога с такими записями в проекте нет. Ваза Forma 04 из hero — другой предмет и не используется для подмены. Цены и productId не выдуманы; просмотр показывает фото предмета из сцены и явное состояние «Пока нет в каталоге».

Для подключения укажите `productId` в `scenes.js`, а в `integrations.js` передайте `products: { async getById(id) { /* загрузить реальный товар */ } }`. Ответ: `{ id, name, price: number, currency: 'RUB', url }`. Идентификатор ответа должен точно совпадать с запрошенным. Цена и ссылка появляются только после получения корректной записи; устаревшие ответы после закрытия карточки игнорируются. Миниатюра показывает именно предмет исходной сцены.

Диалог просмотра поддерживает Escape, закрытие кнопкой и кликом вне карточки, нативное удержание фокуса и возврат к вызвавшей метке. На телефоне он располагается у нижнего края. Под сеткой ссылка использует `inspirationCollection` (если есть), иначе общий `catalog`. Сейчас оба маршрута отсутствуют: ссылка помечена недоступной и объясняет это, `href="#"` и фиктивного конструктора нет.

Проверки: `npm run check`, `npm test`. Тесты проверяют проекцию меток при кадрировании и сохранение области нажатия над подписями во всех сценах на четырёх целевых размерах.

## Коллекция «Олива и мел»

Локальный адрес: http://127.0.0.1:5173/#olive-chalk. Секция размещена сразу после `#in-life`, без изменений существующих стилей секций.

Два отдельных фото `assets/olive/pitcher.png` и `assets/olive/arch.png` восстановлены встроенным imagegen по фотографиям из предоставленного макета. Людей, рук, текста и интерфейса в них нет. Это реконструкции, поэтому мелкие детали могут отличаться. Все файлы подключены. При наличии оригинальных фотографий замените соответствующие файлы.

`olive-data.js` содержит структуру коллекции и две **демонстрационные записи из макета**, а не дубли каталожных товаров: кувшин «Олива», 1,2 л, 7 800 ₽ и подсвечник «Арка», 18 см, 3 400 ₽. Их `key` — только ключи интерфейса, `productId` равны `null`. Цены используются для оформления по макету, покупка отключена. Оба товара следует сопоставить с реальными существующими записями каталога.

Для подключения:

1. Укажите настоящие `productId` в `olive-data.js`.
2. Настройте существующий `integrations.products.getById(id)`. Запись должна возвращать `{ id, name, details, price: number, currency, available: boolean, url, image? }`. Совпадение `id` обязательно; названия, характеристики, цена, наличие, адрес и изображение из каталога имеют приоритет. Новые товары в каталоге не создаются. При ошибке загрузки цена не заменяется цифрой из макета: показывается «—» и кнопка повтора.
3. Настройте существующий `integrations.cart` (`add`, `getCount`, `subscribe`, `open`). `add(id)` должен завершаться только после принятия товара настоящей корзиной. `olive-commerce.js` блокирует одновременный повтор одного ID, освобождает блокировку после ошибки и обновляет существующий счётчик через `updateCartCount` из `app.js`. Подтверждение показывается только после успешного ответа `add`. Ошибка получения счётчика после принятого добавления не выдаётся за неудачную покупку.
4. Укажите реальный маршрут коллекции в `integrations.oliveCollection`.

Пока реальные записи, корзина и маршруты отсутствуют. Ссылки фото/названий и кнопка коллекции не имеют `href`; при активации объясняют недоступность. Нажатие «В корзину» не создаёт локальную покупку и не меняет счётчик. Для подключённого каталога предусмотрены загрузка, ошибка с повтором, отсутствие в наличии; для корзины — загрузка, успех и ошибка. Краткие уведомления видны на экране и объявляются существующей `aria-live` областью.

`npm test` проверяет в том числе двойные нажатия, ошибки/повтор, отсутствие покупки без настоящего ID, приоритет каталога и несовпадение ID. Эти проверки используют изолированные тестовые адаптеры; реальная серверная покупка не проверена, поскольку магазин ещё не подключён.
## «С заботой о вашей покупке»

Локальный адрес: http://127.0.0.1:5173/#customer-care. Секция добавлена после «Характера ручной работы»; разметка, стили и логика предыдущих секций сохранены.

`care.css` использует существующие токены, Prata и Manrope. На десктопе колонки 36% / 59% с промежутком 5%, на небольшом планшете и телефоне одна колонка. Отдельное фото `assets/care/packed-cup.png` (1536 × 1024) восстановлено встроенным imagegen по фотографической области макета. Это реконструкция, детали могут отличаться от оригинала. Файл подключён, людей и рук на снимке нет.

`care-data.js` хранит шесть вопросов. Первый ответ взят дословно из задания и открыт по умолчанию. По последующему указанию пользователя остальные пять ответов оставлены `null`: доставка, оплата, повреждения в дороге, возврат и уход. Никакие сроки, способы оплаты, обещания замены или правила использования изделий не добавлены. Незаполненные вопросы видны, но их кнопки отключены и не открывают пустые панели. После заполнения `answer` реальным утверждённым текстом пункт автоматически становится доступным. Абзацы разделяются пустой строкой; HTML не интерпретируется.

Контактов в исходном проекте нет. `integrations.contact` оставлен `null` по указанию пользователя. «Написать нам» не имеет фиктивного `href`, помечено `aria-disabled` и не входит в порядок Tab. После добавления реального контактного URL в настройку ссылка активируется. Email, телефон и Telegram не выдуманы. Эти данные нужны для завершения подключения блока.

`accordion.js` и `accordion-state.js` обеспечивают максимум один открытый ответ, повторное нажатие закрывает его. Вопросы — нативные кнопки внутри h3, связаны с панелями через aria-controls/aria-labelledby. Состояние отражается в aria-expanded; закрытые панели aria-hidden и inert. Плюс/минус декоративные. Раскрытие через CSS Grid длится 200 мс, высота определяется содержимым; prefers-reduced-motion убирает переходы. Обработчики не меняют адрес и не вызывают прокрутку.

`npm test` включает проверки переключения шести ответов, повторного закрытия, быстрых последовательных активаций и незаполненных пунктов. Для проверки DOM, клавиатуры и длинного текста доступна изолированная тестовая страница http://127.0.0.1:5173/tests/accordion-fixture.html. Её явно обозначенные тестовые ответы не используются в магазине; данные `care-data.js` остаются незаполненными.

`business.css` использует фирменные шрифты и токены. Панель с мягким лавандовым оттенком содержит текст и фотографии в пропорции 42/58. Дополнительный вертикальный кадр занимает 39% ширины основного, выступает вправо внутри внешних отступов панели; подпись находится под снимком. Оба файла подключены; людей и рук нет. Это реконструкции, мелкие детали могут отличаться. Оригинальные фото можно поставить вместо них.

Оба действия открывают нативный dialog: «Обсудим ваш проект» либо «Запрос коммерческого каталога». Обязательны только имя и email/телефон. Тип проекта и описание необязательны. Поля имеют подписи, связанные ошибки, ограничения длины. Tab удерживается в диалоге, Escape и кнопка закрытия возвращают фокус на инициатор. Данные не записываются в браузерное хранилище, не добавляются в URL и не отправляются сторонним сервисам.

В проекте нет B2B-маршрута, каталога, обработчика, политики обработки данных и действующего механизма согласия. Настройка `integrations.business` содержит только `null`:

- `projectUrl` — реальная страница или существующая форма проекта; если задана, основная кнопка ведёт туда.
- `catalogueUrl` — реальный коммерческий каталог или существующий сценарий получения; если не задан, открывается диалог с отдельной темой запроса.
- `privacyUrl` — реальная существующая политика; только при наличии адреса в форме появляется ссылка.
- `consent` — существующий утверждённый механизм `{ label, required: true }`, если он нужен. Текст согласия не выдуман; без настройки чекбокс не показывается.
- `submit(payload)` — обработчик магазина, возвращающий `{ ok: true }` только после успешного принятия сервером. В payload передаются intent, subject, name, contact, projectType (или null), description и, при настройке согласия, consent.

Отправка разрешается только при настроенных `submit` и `privacyUrl`, а также корректной настройке согласия, если оно задано. До подключения видна короткая надпись о недоступности приёма заявок, кнопка отправки отключена. Поля и локальная проверка по потере фокуса доступны, никаких успешных отправок не имитируется. В рабочем сценарии поля и отправка блокируются на время запроса, повторный запрос не создаётся, при ошибке данные остаются в форме, сброс происходит только после `{ ok: true }`. Сроки ответа, скидки и условия сотрудничества не добавлены.

`npm test` включает проверку email/телефона, темы каталога, согласия, отсутствующих подключений, блокировки двойного нажатия, ошибок/повтора и явного ответа сервера. Изолированная страница http://127.0.0.1:5173/tests/business-fixture.html использует явно обозначенный тестовый адаптер в памяти для проверки состояний UI; она не подключена к магазину и не передаёт введённые данные по сети.

## «Письма TERRA»

Адрес: http://127.0.0.1:5173/#newsletter. Блок расположен после бизнеса; футера пока нет, его следует добавить следующим. Существующие секции не изменены. `newsletter.css` использует фирменные токены и шрифты. Чистый фон `assets/newsletter/ceramics-background.png` восстановлен imagegen по макету без текста и UI; это реконструкция. Весь текст и форма — HTML, декоративный фон имеет пустой alt и не принимает нажатия. На узких экранах фон скрыт для читаемости.

Обработчика подписки и страницы конфиденциальности нет. `integrations.newsletter` оставлен с null. Подключите существующий privacyUrl и subscribe({ email }); сервер должен самостоятельно проверять email и возвращать { ok: true, status: 'subscribed' } либо 'confirmation_required'. При отсутствии подключения отправка отключена, политика не получает выдуманного href. Предоставленный текст согласия сохранён без добавления чекбоксов; перед подключением его следует согласовать с реальной политикой магазина.

Клиент обрезает пробелы, проверяет email, блокирует повторную отправку, сохраняет поле при ошибке. Подтверждение по почте отображается отдельно от завершённой подписки. Неоднозначный ответ не считается успехом. Email не логируется, не записывается в хранилища и не передаётся без адаптера. Проверки: npm run check и npm test. tests/newsletter-fixture.html использует только тестовый адаптер в памяти для проверки ошибок и обоих видов успешного ответа; он не подключён к магазину.
